# 기술 스택 및 개발 회고록

## 1. 기술 스택

### Frontend
- **HTML5**
  - 앱의 기본 구조(제목, 입력 영역, Todo 목록, 상태 영역)를 구성
- **JavaScript (Vanilla JS)**
  - 핵심 기능 로직 구현
  - 주요 함수: `addTodo`, `renderTodos`, `toggleTodo`, `deleteTodo`
- **Tailwind CSS (CDN)**
  - 빠르고 일관된 UI 스타일 구성
  - 반응형 카드 레이아웃, 입력창/버튼/목록 아이템 스타일 적용

### Data Storage
- **localStorage**
  - Todo 데이터 영구 저장
  - 새로고침 후에도 목록 유지

### Development Environment
- **Cursor IDE**
- **Git**
  - 작업 이력 관리 및 커밋 기록

---

## 2. 구현한 핵심 기능

- Todo 입력 및 추가
- 빈 값 입력 방지 (`trim` + `alert`)
- Todo 목록 렌더링
- 완료/미완료 토글 (체크박스 기반)
- Todo 삭제 (휴지통 아이콘 버튼)
- 추가/완료/삭제 시 즉시 화면 갱신
- 하단 통계 표시 (총 개수 / 완료 개수)
- localStorage 기반 데이터 영구 저장

---

## 3. 개발 회고

## 잘된 점
- 기능을 단계별로 분리해 구현해서 흐름을 이해하기 쉬웠다.
- `todos` 배열을 단일 데이터 소스로 두고 `renderTodos()`로 화면을 다시 그리는 방식이 안정적이었다.
- UI와 로직을 분리해 유지보수가 쉬워졌다.
  - UI: Tailwind 클래스 중심
  - 로직: JavaScript 함수 중심
- localStorage를 추가해 실사용에 가까운 Todo 앱 완성도를 높였다.

## 어려웠던 점
- 초기에 기능 구현과 UI 수정이 동시에 진행되어 코드 구조가 복잡해질 수 있었다.
- 완료/삭제 버튼을 체크박스/아이콘으로 바꿀 때 기존 로직을 깨지지 않게 유지하는 부분에 신경이 필요했다.
- Git 저장소 루트가 작업 폴더보다 상위에 있어 커밋 범위 확인이 중요했다.

## 해결 방법
- 기능 변경 시 `addTodo`, `renderTodos`, `toggleTodo`, `deleteTodo`의 역할을 명확히 유지했다.
- 화면 변경은 `renderTodos()` 내부 표현만 조정하고, 데이터 처리 로직은 최대한 재사용했다.
- 커밋 전 변경 파일 범위를 점검해 필요한 파일만 기록했다.

## 다음 개선 아이디어
- Enter 키로 Todo 추가 지원
- 접근성(ARIA, 키보드 포커스) 개선
- 사용자 피드백 메시지(alert 대신 화면 내 안내 문구)
- 코드 모듈화(기능별 파일 분리) 및 간단한 테스트 코드 추가

기본 Todo 앱의 필수 기능을 안정적으로 구현하고, Tailwind 기반 UI 개선과 localStorage 영구 저장까지 적용해 실사용 가능한 수준으로 완성했다.
